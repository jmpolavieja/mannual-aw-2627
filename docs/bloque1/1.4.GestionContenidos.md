# 1.4 Gestión de Contenidos: Páginas, Entradas y Taxonomías

Una vez configurado el sitio y revisados los ajustes base del escritorio, el núcleo del trabajo con WordPress consiste en la creación, organización y estructuración de la información. WordPress ofrece dos tipos principales de publicaciones nativas (**Páginas** y **Entradas**) complementadas con un sistema de clasificación denominado **Taxonomías**.

---

## 1. Diferencia entre Páginas (*Pages*) y Entradas (*Posts*)

La correcta elección entre página o entrada es fundamental para mantener una arquitectura web limpia y profesional:

| Criterio | Páginas (*Pages*) | Entradas (*Posts*) |
| :--- | :--- | :--- |
| **Naturaleza del contenido** | Estático, atemporal e institucional. | Dinámico, temporal y cronológico. |
| **Ejemplos típicos** | *Inicio*, *Quienes Somos*, *Servicios*, *Contacto*, *Aviso Legal*. | *Noticias del centro*, *Artículos técnicos*, *Tutoriales*. |
| **Organización** | Jerárquica (Admite páginas padre e hijas). | Taxonómica (Clasificadas por Categorías y Etiquetas). |
| **Sindicación y Feeds** | No se incluyen en feeds RSS/Atom. | Se incluyen automáticamente en el feed RSS del sitio. |
| **Interacción** | Por defecto no permiten comentarios. | Permiten comentarios, debate y moderación. |
| **Visualización** | Accesibles mediante menús de navegación directos. | Organizadas en páginas de archivo ordenadas por fecha. |

---

## 2. Taxonomías: Categorías y Etiquetas

Las **taxonomías** son los mecanismos de clasificación que utiliza WordPress para agrupar y relacionar las entradas del blog o noticias. Se gestionan desde la sección **Entradas**:

### 2.1 Categorías (`Entradas > Categorías`)
* **Jerárquicas:** Permiten crear estructuras de árbol con categorías padre e hijo (por ejemplo: `Informática` -> `Desarrollo Web`).
* **Obligatorias:** Toda entrada debe pertenecer al menos a una categoría. Si no se asigna ninguna, WordPress le asignará la categoría por defecto (*"Sin categoría"* o *"Uncategorized"*).
* **Propósito:** Definir los grandes bloques temáticos o secciones principales del sitio.

### 2.2 Etiquetas / Tags (`Entradas > Etiquetas`)
* **No Jerárquicas:** Son descriptores planos sin relación de subordinación.
* **Opcionales:** Una entrada puede llevar múltiples etiquetas o ninguna.
* **Propósito:** Identificar microtemas o palabras clave específicas que cruzan de forma transversal diferentes categorías (por ejemplo: `HTML5`, `XAMPP`, `Seguridad`).

::: tip Regla de Oro de Usabilidad
Aplica una estructura en "árbol": un sitio no debería tener más de **5 a 8 categorías principales**, mientras que las etiquetas se utilizan libremente para conectar artículos de diferentes categorías bajo un mismo concepto clave.
:::

## 3. Elaboración de Contenidos con el Editor de Bloques (Gutenberg)

WordPress utiliza un sistema de maquetación modular basado en **bloques independientes**. Cada párrafo, imagen, encabezado o tabla es un elemento autónomo con sus propios ajustes de formato.
### Bloques Fundamentales de Maquetación:
* **Texto:** *Párrafo*, *Encabezado* (H1, H2, H3...), *Lista* (viñetas o numerada), *Cita*.
* **Medios:** *Imagen*, *Galería*, *Fondo (Cover)*, *Audio*, *Vídeo*.
* **Diseño:** *Columnas*, *Grupo*, *Separador*, *Espaciador*, *Botón* (Llamada a la acción / CTA).
* **Incrustados (Embeds):** YouTube, Vimeo, mapas de Google Maps.

---

## 4. Estados de Publicación y Visibilidad

Tanto las entradas como las páginas disponen de los siguientes estados en la barra lateral de ajustes del editor:

* **Borrador (*Draft*):** El contenido está guardado pero solo es visible para los usuarios con permisos de edición en el backend.
* **Pendiente de revisión (*Pending Review*):** Estado utilizado por los roles *Colaborador* para solicitar la aprobación de un *Editor* o *Administrador*.
* **Publicado (*Published*):** Accesible públicamente en el frontend.
* **Visibilidad:**
    * **Público:** Visible para todos los visitantes.
    * **Privado:** Visible únicamente para editores y administradores autenticados.
    * **Protegido con contraseña:** Requiere introducir una clave antes de mostrar el contenido.
* **Programación:** Permite fijar una fecha y hora futura para que el CMS publique la entrada automáticamente.

## 🧪 Práctica Guiada de Aula: Estructuración del Portal Corporativo

### Objetivo:
Crear la estructura estática base del sitio y publicar las primeras noticias clasificadas jerárquicamente por categorías.

### Pasos a realizar:

1. **Creación de Páginas Estáticas:**
    * Crea y publica 3 páginas: *Inicio*, *Quiénes Somos* y *Contacto*.
    * Diseña la página *Quiénes Somos* incluyendo un bloque de **Columnas** (2 columnas: foto a la izquierda y texto a la derecha).

2. **Creación de la Estructura de Taxonomías:**
    * Ve a `Entradas > Categorías` y crea:
        * Categoría Padre: `Noticias`
        * Categorías Hijas de *Noticias*: `Académico` y `Eventos`
    * Ve a `Entradas > Etiquetas` y añade: `Altair`, `SMR`, `Proyectos`.

3. **Publicación y Clasificación de Entradas:**
    * Publica 2 entradas de prueba relacionadas con el centro.
    * Asigna la primera entrada a la categoría `Académico` y añade la etiqueta `SMR`.
    * Asigna la segunda entrada a `Eventos` y añade la etiqueta `Altair`.
    * Define una **Imagen destacada** en cada una de las entradas desde la barra lateral de ajustes.

4. **Configuración de Portada Estática:**
    * Ve a `Ajustes > Lectura`.
    * Marca *"Una página estática"*, selecciona como Portada la página *Inicio* y como Página de entradas la página *Noticias*.
