# 1.7 Gestión de Usuarios y Matriz de Roles (RBAC)

En entornos corporativos y educativos, un sitio web rara vez es administrado por una sola persona. WordPress incorpora un modelo de seguridad basado en control de acceso por funciones (**RBAC** - *Role-Based Access Control*), que permite otorgar a cada usuario únicamente los privilegios indispensables para realizar su trabajo (**principio de mínimo privilegio**).

---

## 1. El Modelo RBAC en WordPress

El sistema de seguridad de usuarios de WordPress se fundamenta en dos conceptos técnicos esenciales:

* **Roles (*Roles*):** Perfiles predefinidos que agrupan un conjunto determinado de permisos (por ejemplo, *Editor*, *Autor* o *Colaborador*).
* **Capacidades (*Capabilities*):** Acciones individuales y atómicas que un usuario puede o no ejecutar dentro del sistema (por ejemplo: `edit_posts`, `publish_posts`, `upload_files`, `install_plugins`).

::: info 🛡️ Principio de Menor Privilegio
Nunca se debe utilizar la cuenta con rol de **Administrador** para tareas cotidianas de redacción o publicación de artículos. Si las credenciales de un redactor se ven comprometidas, un perfil limitado a *Autor* o *Colaborador* evita que un atacante instale plugins maliciosos, altere el código del tema o borre la base de datos.
:::

---

## 2. Matriz Comparativa de Roles Nativos

WordPress incluye de serie cinco roles principales para sitios individuales:

| Rol | Nivel de Privilegios | Capacidades Clave | Perfil Típico en Empresa / Centro |
| :--- | :--- | :--- | :--- |
| **Administrador** | Total (100 %) | Control absoluto: gestión de temas, plugins, opciones generales, usuarios y base de datos. | Administrador de sistemas / Responsable TIC. |
| **Editor** | Alto (Contenidos) | Puede crear, editar, publicar y eliminar **cualquier** entrada o página (propias y de otros), y moderar comentarios. | Jefe de redacción / Coordinador de contenidos. |
| **Autor** | Medio (Publicación) | Puede redactar, subir archivos multimedia (`upload_files`) y **publicar directamente** sus propias entradas. No puede editar contenido ajeno. | Redactor de plantilla / Profesor de departamento. |
| **Colaborador** | Bajo (Borradores) | Puede redactar y modificar **únicamente sus propias entradas**, pero **no puede publicarlas** ni subir archivos multimedia. | Alumno en prácticas / Redactor externo en revisión. |
| **Suscriptor** | Mínimo (Lectura) | Solo puede gestionar su propio perfil de usuario y acceder a contenido privado o comentar si está restringido a registrados. | Alumno / Lector registrado del portal. |

## 4. Gestión de Usuarios desde el Escritorio (`wp-admin`)

La administración de cuentas se realiza desde la sección **Usuarios** del menú lateral:

### 4.1 Alta de Nuevos Usuarios (`Usuarios > Añadir nuevo`)
Al crear una cuenta, se deben configurar los siguientes parámetros:
* **Nombre de usuario (*Username*):** Identificador único para el inicio de sesión. Una vez creado, WordPress **no permite modificarlo** directamente desde el panel (requeriría tocar la base de datos).
* **Correo electrónico:** Obligatorio y único en el sistema. Se utiliza para notificaciones del sistema y recuperación de credenciales.
* **Contraseña:** WordPress genera automáticamente contraseñas seguras y robustas.
* **Perfil (*Role*):** Selección del rol asignado según la responsabilidad encomendada.

### 4.2 Ajustes Generales de Registro (`Ajustes > Generales`)
* **"Cualquiera puede registrarse":** Por seguridad, esta casilla debe permanecer **desactivada** en sitios corporativos estándar, salvo que se trate de intranets o plataformas de suscripción abierta.
* **Perfil por defecto para nuevos usuarios:** Si el registro está abierto, debe ser siempre **Suscriptor** para evitar escaladas de privilegios no deseadas.

## 🧪 Práctica Guiada de Aula: Auditoría de Perfiles y Control de Acceso

::: info 📌 Hito Evaluable en Google Classroom
Al finalizar las comprobaciones con las diferentes cuentas, sube la captura de la tabla de usuarios y la matriz validada a la tarea **"Práctica 1.7: Auditoría RBAC y Gestión de Usuarios"** en Google Classroom.
:::

### Objetivo:
Crear cuentas de usuario representativas de los distintos perfiles de WordPress y verificar experimentalmente las limitaciones de permisos de cada una desde el navegador.

### Pasos a realizar:

1. **Creación de Cuentas de Prueba:**
    * Accede a tu panel con el usuario administrador.
    * Ve a `Usuarios > Añadir nuevo` y crea tres usuarios con contraseñas que recuerdes con facilidad:
        * Usuario: `editor_altair` | Perfil: **Editor**
        * Usuario: `autor_altair` | Perfil: **Autor**
        * Usuario: `colaborador_altair` | Perfil: **Colaborador**

2. **Auditoría de Acceso con `colaborador_altair`:**
    * Abre una **ventana de incógnito** en tu navegador e inicia sesión con el usuario `colaborador_altair`.
    * Observa el menú lateral: comprueba que **no aparecen** las secciones *Plugins*, *Apariencia*, *Ajustes* ni *Medios*.
    * Crea una nueva entrada: verifica que el botón principal no dice *"Publicar"*, sino **"Enviar para revisión"**.

3. **Flujo Editorial con `editor_altair`:**
    * Cierra sesión en la ventana de incógnito e inicia sesión como `editor_altair`.
    * Accede a `Entradas > Todas las entradas` y localiza la entrada enviada por el colaborador.
    * Revisa el texto, asígnale una categoría y haz clic en **Publicar**. Comprueba cómo el editor tiene capacidad de validar y dar salida a contenidos ajenos.

4. **Evidencias para Classroom:**
    * Captura 1: Vista de `Usuarios > Todos los usuarios` desde la cuenta de administrador donde se visualicen los 4 roles creados.
    * Captura 2: Pantalla del editor de bloques del usuario `colaborador_altair` demostrando que carece del botón directo de publicación.
